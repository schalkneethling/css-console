The css-console playground

Nine annotated declarations, and one browser console report showing what the engine resolved for each of them.

How to read this page

css-console turns a comment in your CSS into a report of what the browser resolved. Every case below is annotated in examples/playground/playground.css using the grammar css-console: <log-level> [property-list] [label="..."].

  1. Serve the repository with vp dev, and open /examples/playground/index.html.
  2. Open the browser console, and reload the page.
  3. Expand the group labeled with the case you are reading, such as [case-1].

A group title names the source, the line, the column, and the resolved selector, and each line inside reads property: authored value → resolved value. A value ending in (contested) carries a handoff line naming why another declaration may have contributed, and passes the question to your developer tools. The report never claims a winner.

Case 1 A custom function, resolved at every call site

A custom function has no value of its own, only a result at each call site, and the number arrives from a custom property on the matched element. Two rules call --case-1-step(), and one of those call sites matches three elements with different units.

--case-1-unit: 8px
--case-1-unit: 12px
--case-1-unit: 16px

The second call site is the padding on this paragraph, driven by a smaller unit.

In the console: one group titled [case-1] --case-1-step, with a collapsed group per call site. Each names its destination property, authored arguments, and selector, then tables one resolved value per matched element.

The source

/* css-console: log label="case-1" */
@function --case-1-step(--n) {
  result: calc(var(--case-1-unit) * var(--n));
}

.case-1-unit-8 { --case-1-unit: 8px; }
.case-1-unit-12 { --case-1-unit: 12px; }
.case-1-unit-16 { --case-1-unit: 16px; }

.case-1-bar {
  inline-size: --case-1-step(3);
}

.case-1-note {
  --case-1-unit: 6px;

  padding-inline-start: --case-1-step(2);
}

Case 2 A color mix, resolved once per theme

The two declarations below are character for character identical, and they paint different colors, because each section supplies its own brand color. The report shows the color-mix() you wrote beside the color the engine computed in oklch and serialized.

Warm theme

Cool theme

In the console: two groups titled [case-2], one per themed selector. Each holds one line with a color swatch, the authored color-mix(), and the resolved color.

The source

.case-2-warm { --case-2-brand: oklch(0.68 0.18 45); }
.case-2-cool { --case-2-brand: oklch(0.62 0.16 250); }

/* css-console: log background-color label="case-2" */
.case-2-warm .case-2-chip {
  background-color: color-mix(in oklch, var(--case-2-brand) 60%, white);
}

/* css-console: log background-color label="case-2" */
.case-2-cool .case-2-chip {
  background-color: color-mix(in oklch, var(--case-2-brand) 60%, white);
}

Case 3 A container unit, resolved against its container

A cqi length is one percent of the inline size of the nearest query container, so one declaration has as many values as it has containers. The two captions below share a rule and sit in containers of different widths.

Wide container

Narrow container

In the console: one group titled [case-3] .case-3-caption, with a row per caption. Both rows read 6cqi as authored, and two different pixel values as resolved.

The source

.case-3-container {
  container-type: inline-size;
}

.case-3-wide { inline-size: 32rem; }
.case-3-narrow { inline-size: 14rem; }

/* css-console: log font-size label="case-3" */
.case-3-caption {
  font-size: 6cqi;
}

Case 4 A clamp, at both bounds and between them

A clamp() has three regimes, and the declaration does not say which one an element is in. Here the fluid middle is a per-element custom property, so all three show at once: the first bar sits at the lower bound, the second is fluid, and the third sits at the upper bound.

--case-4-pull: 2rem
--case-4-pull: 13rem
--case-4-pull: 40rem

The first bar and the third bar ignore their custom property, which is what a bound does.

In the console: one group titled [case-4] .case-4-bar, with three rows. Every row repeats the same authored clamp(), and the resolved values are the lower bound, a value between the bounds, and the upper bound.

The source

.case-4-pull-low { --case-4-pull: 2rem; }
.case-4-pull-mid { --case-4-pull: 13rem; }
.case-4-pull-high { --case-4-pull: 40rem; }

/* css-console: log inline-size label="case-4" */
.case-4-bar {
  inline-size: clamp(6rem, var(--case-4-pull), 24rem);
}

Case 5 A custom property, at the end of its inheritance chain

The leaf rule below reads var(--case-5-tone), and which declaration of that property arrives depends on where the leaf sits in the tree. Both leaves match the one rule, and only one of them inherits the tone declared halfway down.

A leaf directly under the root, which declares the tone.

A leaf under a branch, which declares the tone again.

In the console: one group titled [case-5] .case-5-leaf, with a row per leaf. Both rows were authored as var(--case-5-tone), and the resolved colors differ.

The source

.case-5-root { --case-5-tone: oklch(0.55 0.15 250); }
.case-5-branch { --case-5-tone: oklch(0.52 0.19 25); }

/* css-console: log color label="case-5" */
.case-5-leaf {
  color: var(--case-5-tone);
}

Case 6 A pseudo-element sized by its generated content

A ::before pseudo-element has no element in the document, so it cannot be selected or measured the way an element can. Its content comes from an attribute and its width follows from that content, so css-console reads the pseudo-element directly.

In the console: one group titled [case-6] .case-6-tag::before, with a row per tag. Every row reads max-content as authored, and the resolved widths grow with the label.

The source

/* css-console: log width label="case-6" */
.case-6-tag::before {
  content: attr(data-tag);
  width: max-content;
}

Case 7 A random value, behind a feature query

The random() function returns a value the source cannot state, and a browser may not implement it yet, so the declaration sits behind @supports (width: random(1px, 2px)). css-console evaluates a rule's conditions against the live engine. Where the feature query fails, the group still opens, from the source, and reports nothing, because nothing applied.

This browser does not support random(), so the guarded declaration never applied and the console group for this case is empty. That empty group is the report: the rule is in the source, and this engine is not using it.

In the console: one group titled [case-7] .case-7-die, holding one resolved width per bar where random() is supported, and nothing at all where it is not.

The source

@supports (width: random(1px, 2px)) {
  /* css-console: log width label="case-7" */
  .case-7-die {
    width: random(4rem, 12rem);
  }
}

.case-7-notice { display: none; }

@supports not (width: random(1px, 2px)) {
  .case-7-notice { display: block; }
}

Case 8 A nested rule, and the selector it resolves to

CSS nesting substitutes the parent rule into the child through :is(), which produces a selector no line of the source contains. css-console resolves nesting before it matches, so the group title is the selector the engine used rather than the spelling the stylesheet carries.

In the console: one group titled [case-8] whose selector is a nest of :is() wrappers. Compare it to the source below, which does not contain it.

The source

.case-8-panel {
  .case-8-row {
    /* css-console: log border-color label="case-8" */
    .case-8-dot {
      border-color: oklch(0.62 0.19 25);
    }
  }
}

Case 9 A shorthand competing with an annotated longhand

The rule below sets margin-left, and then sets margin, which sets margin-left again. Reporting only the annotated declaration would mislead, because the resolved value did not come from it. The guard reports that the declaration may not be the sole contributor, names why, and hands you the live element rather than a winner.

This card is annotated to report margin-left: 3rem, and it is sitting at a margin of 0.5rem.

In the console: one group titled [case-9] .case-9-card, holding a line ending in (contested) and a handoff line reading contested (competing-declaration) with an instruction to inspect the element. The live element travels with that line, so clicking it takes you to the box.

The source

/* css-console: log margin-left label="case-9" */
.case-9-card {
  margin-left: 3rem;
  margin: 0.5rem;
}
